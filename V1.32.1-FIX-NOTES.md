# Version 1.32.1 - JavaScript Fix

## Problem
The sorting buttons appeared on the page but didn't work. Browser console showed:
```
Uncaught SyntaxError: expected expression, got '<'
```

## Root Cause
The JavaScript was output inline within the shortcode's HTML output (lines 7447-7488). WordPress applies the `wpautop()` filter to shortcode output, which automatically wraps content in `<p>` tags and adds `<br />` tags. This broke the JavaScript syntax:

```html
<p>	<!-- Sorting JavaScript --><br />
	<script>
	(function() {
		document.addEventListener('DOMContentLoaded', function() {
			const sortButtons = document.querySelectorAll('.esop-advisor-directory .sort-btn');
			const grid = document.querySelector('.esop-advisor-directory .advisor-grid');</p>
<p>			if (!sortButtons.length || !grid) return;</p>
```

## Solution
Moved JavaScript to a separate function that outputs in `wp_footer`, exactly like the CSS function does.

### Changes Made:

**1. Created new function `esop_advisor_directory_js()` (added after line 7314):**
```php
add_action( 'wp_footer', 'esop_advisor_directory_js', 10 );

function esop_advisor_directory_js() {
    global $esop_advisor_directory_used;
    if ( empty( $esop_advisor_directory_used ) ) {
        return;
    }
    ?>
    <script id="esop-advisor-directory-js">
    (function() {
        document.addEventListener('DOMContentLoaded', function() {
            // ... sorting logic ...
        });
    })();
    </script>
    <?php
}
```

**2. Removed inline JavaScript** (deleted lines 7447-7489 from shortcode output)

**3. Updated version to 1.32.1** with changelog

## Technical Details
- JavaScript now outputs via `wp_footer` at priority 10 (after CSS at priority 5)
- Uses same global flag pattern as CSS: `$esop_advisor_directory_used`
- JavaScript only loads on pages that use the `[esop_advisor_directory]` shortcode
- No longer processed by `wpautop()` filter since it's not part of shortcode content
